# 直播透明小游戏

把想法做成可试玩、可叠在直播画面上的小游戏。默认中文交付，优先复用现有宿主协议和项目结构；用户指定其他运行形式时保留该选择。

## 接到需求

先读目标插件的说明、入口、构建脚本和事件适配器。只检查相关目录，不扫描整个素材库、依赖或历史归档。已有作品就地迭代；新作品放独立目录。

用一小段话确定：**主播操作 → 观众干预 → 可见反馈 → 回合目标/失败条件 → 重开**。同时说明宿主、画布范围、交付形式和真实接入状态。已有上下文足够就直接实现；只追问会改变玩法或接入方式的缺口。没有宿主协议时先完成离线模拟，不杜撰SDK、端口和平台消息字段。

选择最小合适实现：简单2D用DOM/Canvas；复杂碰撞或3D沿用项目已有库。单HTML交付允许开发时拆分源码再打包；离线版本把所需库、图片、字体、音频内嵌或随包提供。

## 制作顺序

1. **先完成可玩的闭环。** 玩家看懂、能操作、能成功或失败、能重开。原型验证通过后可以继续完善该代码，仅在结构不适合时重写。小插件不建立工作室层级、冲刺文档或引擎迁移流程。
2. **让互动有戏剧性。** 帮忙、捣乱、逆转需有清楚的因果、预兆、效果和恢复过程；观众署名不遮挡目标。局部强调动画服务玩法，避免整屏遮罩、无休止抖动和声音轰炸。连续干预有上限与喘息空间。
3. **补齐直播运行约定。** 阅读 [runtime-contract.md](references/runtime-contract.md)。页面、舞台和画布保持alpha透明；预览底色与直播输出分离。统一输入与效果入口，暂停冻结游戏时钟，临时效果按游戏时间恢复。明确候场、重开、切场景及刷新行为。
4. **按需接入宿主。** 需要弹幕/礼物时阅读 [event-adapter.md](references/event-adapter.md)。模拟与真实输入共享业务执行路径；协议归一化由独立适配器负责。已有协议和用户设定优先于新项目默认值。
5. **边玩边修。** 使用 [acceptance.md](references/acceptance.md) 中与本次改动相关的检查。代码可解析不等于能玩；至少实际运行一个完整闭环并查看画面。证据只覆盖实际测过的环境。

## 可复用起点

新建无框架2D插件时可复制 [overlay-starter.html](assets/overlay-starter.html)。这是透明落球演示，包含有界候场、暂停/重开、去重和预览底色，**不是完整游戏或已接通直播的平台适配器**。修改玩法与美术后交付，不把演示当成用户要求的成品。

普通打开为透明输出；加 `?preview=1` 打开带底色与控制台的试玩，F2可展开控制台。演示不保存分数、球或待执行事件，不建立网络连接。

模板逻辑回归：`node scripts/test-starter.cjs`（相对本技能目录）。测试只检查模板，不代表新游戏、浏览器宿主或真实直播已验收。

## 交付

提供实际HTML/资源包、短操作说明和验证范围。区分“离线试玩可用”“适配代码已实现”“真实宿主已联调”。只有需要时附参数、备份或发布文档。说明入口、尺寸、控制方式、真实接入所缺资料与限制，不声称未执行的长时间运行或跨宿主兼容测试。
