# 事件适配与礼物语义

本文件是内部接口建议，不是任何平台的官方协议。

## 输入与数量

读现有SDK/适配器、说明或脱敏样本，确认事件名、ID、礼物标识、数量和连击语义。保留现有宿主方法。未知协议时做模拟入口，不猜WebSocket地址、端口或全局SDK名。

内部可归一化成 `{ id, kind, actor, giftKey, count, receivedAt }`；count为本次新增数量。按项目调整结构。模拟与真实消息在归一化后走同一业务入口。

- 校验有限整数、长度、枚举、最大批量。昵称当文本显示，不拼innerHTML。异常消息有诊断，不终止主循环。
- 有ID时用来源命名空间+ID去重，缓存有容量与保留时间。失败事件能否重试需明确；“同昵称+同礼物”不是唯一ID。
- **增量1、2、3合计6；累计1、2、3合计3。** 累计连击只在已确认协议后按来源、用户、礼物和连击会话ID算增量。处理重复、结束包、归零/新会话、乱序；没有会话依据不保证可靠计算。
- 无ID时按协议尽力处理并说明限制；模拟可造ID，但不能把真实重发包换成随机ID后宣称已去重。

## 候场与效果

接收与执行分开。待开始/暂停时按约定候场，设容量、**真实时间过期TTL**和溢出策略；继续后限速释放，不能一帧补发全部。明确结束时接收规则，重开清理旧候场。

刷新不自动恢复外部命令；游戏存档不等于事件事务。断线重连不回放历史礼物；需要回放时必须有幂等依据。

数量映射与视觉对象数分离：5件礼物可生成5球，或依明确规则合并成标记×5的一球。计分按实际玩法执行，不能入队即当作完成目标。超限告知未执行数量，不静默截断。

真实接入按需求提供连接/断开、接收开关与状态。已有自动接收行为未经要求不改；新项目由用户主动开启真实接收。模拟不伪装真礼物。

## 连接边界

postMessage校验source、结构和可验证origin。file来源可能为null，不能仅凭null放行所有窗口；结合来源窗口和会话握手。

WebSocket重连有界退避，关闭时取消重连，避免重复订阅。多实例可能同时接收/写入时先确认宿主行为，再做实例仲裁；BroadcastChannel不保证跨origin/存储隔离互通。

分别记录模拟输入、协议样本回放、真实平台送礼；前两项不替代第三项。
