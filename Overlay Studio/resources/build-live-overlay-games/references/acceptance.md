# 按改动选择验收

流程：打开交付入口 → 开始 → 玩家操作 → 干预 → 胜/负或目标完成 → 重开。

| 检查 | 观察 |
|---|---|
| 透明 | 页面/舞台无实色背景；透明截图有alpha；在浅、深及复杂底图上可读 |
| 入口 | 单文件在file路径、断网下打开；HTTP通过不能代替file通过 |
| 输入 | 主要输入有效；pointercancel与失焦不粘键；缩放后碰撞与指针一致 |
| 生命周期 | 连点开始不加速；暂停冻结；切出再回不跳时；重开清空旧效果与候场 |
| 规则 | 能完成/失败/重开；重复事件不多执行；增量和累计样本结果正确 |
| 突发 | 按目标负载注入，例如100条/秒；对象、日志、队列有界；拒绝/过期可观察；释放平滑 |
| 恢复 | 禁用存储/坏JSON仍可玩；刷新不重播旧礼物；按要求恢复进度但先暂停 |
| 声音 | 未解锁音频不致命；静音有效；无声音叠加风暴 |
| 布局 | 目标尺寸及更窄尺寸无溢出；设置可关闭；预览底色不混入透明输出 |

使用可用浏览器工具看画面、操作与控制台；必要时自动测试事件数量和生命周期。源码字符串检查不等于功能验证。

长时间运行按需要实测，报告真实时长、负载和内存/对象趋势；逻辑时间快进不等于等时长实际运行。性能根据设备测量，不把60fps当未经验证的保证。

只有进入OBS/菘蓝/整蛊机并观察过，才能声称宿主验证通过。无法进入宿主仍交付已完成部分，并明确缺少的联调。真实平台送礼单独列出。

交付只需：入口与操作、已验证环境和结果、接入状态、实际剩余限制。必要截图附后。
