# V4.4 下拉依赖与 OBS 兼容性检查

用户确认故障发生在接收者的 OBS 浏览器源交互窗口。

## 证据与结论

- V4.3 的四种静态下拉和每关颜色下拉均为原生 select。没有外部 UI 库、CDN 脚本或本机 node_modules 依赖。
- 官方历史问题 https://github.com/obsproject/obs-studio/issues/5498 记录了 OBS 浏览器源原生 select 弹层不显示。CEF OSR 对原生弹层存在宿主绘制要求，这是与本次描述一致的风险；未访问接收者机器，不能断言其具体版本的唯一根因。
- V4.4 使用 inline-select.js 在 DOM 内生成按钮和列表，原生 select 仅作为隐藏状态。全部样式/逻辑由 build.mjs 内联到单 HTML。
- 菘蓝 SDK / 本机 9910 WebSocket 仍只用于礼物。开发预览 8137 不在运行资源依赖中，不能把开发机地址当作分享链接。

## 修复细节

- 四个静态选择项和所有动态关卡色彩项统一适配；变更事件沿用现有逻辑。
- 支持键盘、禁用状态、点外部/Esc 关闭，弹层视口内向上/下展开，不受设置面板滚动裁切。
- 画板异步重建期间临时禁用选择项，结束后恢复，避免刚打开的列表被重新渲染销毁。
- 弹层跟随父容器滚动定位，不依赖本机窗口式弹出菜单。

## 验证

qa-dropdowns.mjs 对照压缩包 V4.3 和新版 HTML；启用新的浏览器上下文，拦截外部 HTTP 请求与 WebSocket，检查所有静态/动态项目、实际选项点击、键盘、刷新、禁用状态、1280×720 和 960×540 视口，并在 iframe 中拒绝 localStorage 与 IndexedDB。结果见 tmp/qa-dropdowns/summary.json。原生弹层调用 0，外部素材请求 0，脚本错误 0。

62 项单元测试通过。qa-magnifier-mode.mjs 已迁移为点击可见 DOM 选项并通过。旧测试脚本与录制脚本通过 qa-select-helper.mjs 使用同一操作路径，不再用 selectOption 绕过真实选项 UI（旧版对照除外）。

验证使用本地 HTTP，非对方具体 OBS/CEF 实机，也不冒充 file URL 打开验证。交付 ZIP 逐字节核对 HTML、PDF 与视频。
