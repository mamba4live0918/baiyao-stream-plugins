# V5.6.1：摇桌掉很多豆时不再卡顿；新镊子与拼豆笔模型

日期：2026-09-26。本版建立在 V5.6（自定义互动级别与双宿主演示）之上，互动级别、说明书和演示视频都没有改动。

## 摇桌子掉很多豆时的卡顿

原因有三处：

1. **每掉一颗豆就存一次档**：这是最主要的卡顿。一次摇掉上千颗时，整个存档要序列化上千次，而且存档越来越大，主线程会停好几秒。
   - 现在同一次摇晃掉的豆逐颗记账，但提示、掉落列表、进度状态和存档合并成一次。
2. **每颗掉落豆是单独的网格**：46 格板全掉时，每帧约 2700–2900 次绘制，加上阴影还要翻倍，而且要一直等到把掉落豆全部移走。
   - 现在不在柱上的豆（正在落下、被摇松、散在桌上）合批成一个实例网格，全掉也只多一次绘制。
   - 点击拾取改为对实例网格做射线检测，点不中时仍按屏幕距离找最近的豆，和以前一样。
3. **物理计算**：
   - 去掉连续碰撞检测：豆子每步最多移动约 0.1 格，用不着。
   - 每步最多新建 24 个刚体，分几帧陆续加入。
   - 同时做真实碰撞的豆按「工作台画质」限制：标准 48、高 96、超高 128。
   - 其余的豆走简化抛物线，落地后滑一小段就静止，不再排队等物理名额。以前一次大摇晃会让物理引擎忙几十秒。
   - 静止的掉落豆不再每帧上报位置。
   - 某一帧卡了之后，最多补算 3 步，不会越补越卡。

同时修正了一个显示问题：超出物理名额的掉落豆以前落到桌面高度，看起来像沉进了豆板。现在落在板上的豆停在柱顶，落在板外的停在桌面。

## 新镊子与拼豆笔

- **镊子**：换成不锈钢精密弯头镊。
  - 拉丝不锈钢钢片、抛光尖头、橄榄绿硅胶防滑握套、尾部焊接头。
  - 钢件有单独的环境反光，不影响其它物体。
  - 钢片宽面朝上倾斜，俯视镜头下也看得清楚。
  - 停放的镊子和手持镊子共用这套模型。
- **拼豆笔**：换成透明笔管，里面装着当前颜色的豆。
  - 笔管里的豆数与手里剩余一致（最多显示 12 颗），放一颗少一颗。
  - 另有硅胶笔帽、钢笔夹和出豆口。
- 实现在新增的 `src/tool-models.js`。
- 演示视频录制于 V5.6，里面仍是旧的镊子外观。

## 在白曜重工里「3D 物理初始化失败」

白曜重工给导入插件的页面加了内容安全策略：`script-src 'unsafe-inline'`，其中没有 `'wasm-unsafe-eval'`。所以 Rapier 物理引擎的 WebAssembly 无法启动，左下角提示「3D 物理初始化失败，当前仅能使用画面」，落豆、摇桌、散落都失效。成品后台线程（Blob Worker）也被同一条策略拦下。

- 现在 WebAssembly 被拦时自动改用纯 JS 的简化物理（`physics.mode === 'lite'`），不再弹这个错误。
  - 落豆时用脚本动画落到柱上；摇掉的豆按抛物线飞出，落地后滑一段停下，碰到桌边会弹回。
  - 散落、拾取、复原、存档都和完整物理一致。
  - 唯一的区别：掉落的豆之间、豆与柱之间不做碰撞。
- 成品后台线程被拦时，本来就会改在当前线程生成，结果相同，熨烫结束时会停顿几秒。
- 菘蓝、OBS 直接打开本地文件、普通浏览器里不受影响，仍用完整物理。
- 想让白曜里也用完整物理，需要白曜在插件页的 CSP 里加上 `'wasm-unsafe-eval'`，另加 `worker-src blob:` 让成品在后台线程生成。这要改白曜重工本身（`src/obs-source-host.cjs`），本版没有改。
- 验证：`qa-csp.mjs` 用和白曜完全相同的 CSP 提供页面，结果如下，页面错误 0：
  - 自动进入简化物理，不提示初始化失败；
  - 帮拼 → 摇掉 → 点掉掉落豆 → 托盘打翻与五段复原都正常；
  - 补齐图案后熨烫，成品在当前线程生成（35.7 万顶点）。
- `tests/physics.test.mjs` 新增简化物理测试：落豆套柱、全部散落后留在桌面、静止后不再上报、复原。`npm test` 共 93 项。
