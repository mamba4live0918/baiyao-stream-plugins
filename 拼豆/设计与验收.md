# 拼豆直播插件：设计与验收

## 当前版本 V5.6

当前操作、两套宿主安装方式和自定义互动级别见 [V5.6 说明](docs/V5.6-自定义互动级别与双宿主演示.md) 与 `交付/使用说明.pdf`。九种互动可分别管理 0–20 个级别；下方为旧版设计与验收记录，涉及固定三档、板格上限和早期 PDF 页数的描述只对应当时版本。

## V3 历史操作约定

双击空白打开菜单；四个部件独立双击解锁、拖动/缩放、双击锁定。默认透明，按住可配置按键（默认 M）局部放大，提示显示 P 色号。当前用色紧密排列，摇落豆必须手动拾取。九种互动各三档，五种熨烫沿用 V2。详见六页 PDF 与 design-qa.md；下方早期方案与此冲突时以本节为准。

## 目标

为直播间制作透明背景的独立 HTML 插件。主播用镊子从装豆盒逐颗取空心拼豆，套在 3D 柱板上；观众通过菘蓝整蛊机礼物改变拼豆过程。画面适合 OBS 浏览器源，也能在普通浏览器直接操作。完成作品后选择视觉熨合样式、观看熨烫动画，生成可旋转、缩放及查看正反面的真 3D 成品；浏览器作品库保存 3D 数据供复看，可下载 GLB 模型文件，透明底 PNG 仅作分享附加导出。

## 主要交互

1. 初始板 16×16，可改为 16–48 的方板。40 张以上原创预设按主题分类；PNG/JPEG/WebP 上传被采样并量化到内置豆色盘。透明像素不产生任务。改图/改板前确认当前进度处理。
2. 板上未拼位置显示半透明的目标豆，已拼豆始终真实显示。每次必须从装豆盒拿一颗，拖到指定柱位；错色仍可放下并标出，主播可用镊子取走。完成判定要求目标非空位颜色全部正确且没有多余豆。
3. 3D 板和豆由 Three.js 绘制；Rapier 3D 处理已经离柱的豆的运动和碰撞。每颗豆的孔由多个环段碰撞体形成，柱有实体碰撞。正常已套柱的豆保持在位；摇晃达到释放阈值后转为动态体，可能掉落。该方案是“套柱状态 + 真 3D 碰撞”的混合物理，性能上限通过最多活动豆数控制。
4. 礼物效果：摇桌、随机换掉已拼豆颜色、帮拼、减豆、隐藏提示、打翻装豆盒托盘、暂没收镊子、限时多豆笔、再拼一个。各效果支持礼物名、数量系数和测试按钮；按到达顺序结算。摇桌可能使已拼豆脱柱；打翻只使装豆盒/托盘里的库存豆散落，已拼板保持原样。托盘复原时空格必须一次次按（长按重复无效），进度缓慢回落；每满一段只让部分库存豆飞回盒中或托盘。
5. 菘蓝宿主内优先使用 `SonglanPlugin.onGift`；独立页回退连接 `ws://localhost:9910` 并发送 `identify`。礼物接收数量使用本次增量，避免同时连接两个来源。连接状态明示。
6. 熨烫样式提供轻熨、标准、融合三种游戏视觉外观；动画展示熨斗扫过，再出现可拖动旋转、滚轮缩放和翻看背面的 3D 成品。作品的 3D 豆色网格与样式保存到当前浏览器 IndexedDB，可在作品库点「3D 检视」重新打开及删除；熨烫弹窗和作品库检视均可下载 GLB 模型，透明底 PNG 为附加静态分享图。浏览器作品库与下载文件互不自动同步。参考 Perler 标准熨合，豆边融合后中心孔仍开放且通常翻面熨另一侧；融合档仅视觉模拟孔更小、表面更平，不宣称是现实推荐标准。

## 可靠性与限制

- 板面、图案、豆色、散落状态、礼物效果、追加轮次、设置持久化；刷新后不重复执行已结算礼物。存储失败则提示当前页面临时使用。
- 图片上传限大小与像素数，先解码再替换；无效文件不得覆盖当前图案。浏览器实际存储空间有限，作品库保存失败时明确提示，并提供当前可用的分享/模型文件导出。
- 独立 HTML 内联 JS、CSS、WASM、字体/小图资源，不调用开发服务器，不依赖本地文件路径。WebGL 不可用时给出可操作的 2D 降级板，不假称已运行 3D 物理。
- 3D 物理采用有限活动豆优化，默认推荐 16–24 板；大板会降低装饰精度并限制同时散落数量。刷新恢复保存状态，但不保证不同设备浏览器共享存档。
- 礼物名称可由用户配置；菘蓝真实直播间具体礼物须使用现场发送验证，因为宿主消息没有可靠事件 ID，断线期间也没有补发保证。

## 交付验收

- 单 HTML 在 `file://` 打开，页面透明，40+ 预设和上传、板大小、取豆放豆、错色取走、完成/烫制/3D 检视与作品库复看可操作；GLB 可从两处下载，PNG 是附加分享导出。
- 菘蓝 SDK 模拟与 9910 WebSocket 消息分别触发配置礼物；重复绑定不会双收。手动测试按钮可在无宿主时演示全部效果。
- 轻/重摇对已拼豆的影响、托盘库存豆散落和五段空格复原可见；长按空格只算一次。刷新保留进度。
- 最终 ZIP 内的 HTML 与 PDF 与工作文件逐字节一致；实际从 ZIP 解出的 HTML 检查核心交互和透明背景。演示视频覆盖从加载插件到拼豆、礼物、熨烫和保存。

## 实物熨烫资料

- [Perler 标准熨合方法](https://perler.com/blogs/projects/standard-fusing-method)：适当熨合后保留中心孔，冷却后翻面处理另一侧；避免过熨导致中心闭合。
- [Perler 常见问答](https://perler.com/pages/frequently-asked-questions)：说明中心孔、热量与表面平整程度的关系，并建议熨合两面。
- [Hama 使用方法](https://www.hamabeads.com/how-to-use/)：逐颗套柱、隔纸打圈熨烫、冷却后取下。

以上用于校准外观描述。插件的三个选项是视觉模拟，不给出实物温度、时间或强度保证。
