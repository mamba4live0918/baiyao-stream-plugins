异世界访客登记系统 · V2
BYSL | 2026-09-22

一、导入菘蓝
1. 解压分享包，在菘蓝的自定义插件入口选择「异世界访客登记系统-1.html」。
2. 直播画面默认全透明，名册在右侧；不需要安装依赖或运行开发服务器。
3. 双击插件画面，或在插件有键盘焦点时按 Esc，打开控制台。点击面板外侧或关闭按钮退出。
4. 在「概览」点「开始预演」检查效果。退出预演后恢复真实名册；直播前确认左上角的「演示中」提示已经消失。
5. 在菘蓝正常接入直播间后，发送「登记」和「转正祝福」进行一次实际弹幕联调。

二、观众怎么玩
登记：整条弹幕发送「登记」，去掉首尾空格后匹配。登记会显示昵称并加入循环滚动名册，重复登记不增加人数，也不加分。
升级：已登记观众发送普通有效弹幕，默认每条 +1 分，同一个人 10 秒内只计一次。礼物默认每个 +1 分，数量直接乘积分，不按礼物价格。设置为 0 可关闭对应计分。点赞、入场和关注不计分。
称号：旅人 0 分起（★）；星使 10 分起（★★）；守护者 50 分起（★★★）。控制台可改门槛，守护者门槛必须大于星使门槛。
祝福：发送「转正祝福」，显示带观众昵称的转正纪念星光特效。无需先登记，祝福本身不加分。默认同观众 30 秒冷却，按到达顺序展示；祝福和升级合计最多等待 30 条，满额后忽略新特效，正常积分照常处理。

三、当前观众识别方式（重要）
已按本机菘蓝 4.0.5 的实际插件接口适配。该版本向自定义插件发送昵称和头像，没有发送稳定平台用户 ID。
本版按用户确认，默认使用「昵称＋头像」作为档案标识：
- 同名但头像不同，会分别登记。
- 观众改名后，主播可在「名册备份」中修改其原档案名字，将新昵称与原积分绑定；换头像仍须另行核对。
- 同名且同头像无法区分；事件没有头像时只能按昵称识别。
- 如果未来菘蓝开始发送稳定 userId / uid / idStr / secUid，本版会优先使用该 ID；不会猜测并自动合并旧的昵称头像档案。
头像地址仅用于身份识别，不会加载或显示远程头像图片。
请直播时只保留一个接收事件的插件实例。若同浏览器另一个页面已更新存档，本页会暂停写入并提示，以免覆盖新记录；先导出本页备份，再刷新读取最新名册。

四、外观与透明上屏
旅人、星使、守护者的名册小卡与中央祝福/晋级大卡现在使用各自卡面：青绿色提灯与旅途、紫色星轨仪、金色翼盾；边框轮廓也不同。图案内置 HTML，卡片外及无图案处仍透明。
未登记观众发送祝福时采用旅人卡面，但不会因此自动登记或得到积分。在「开始预演」后可点「旅人卡面／星使卡面／守护者卡面」分别检查中央大卡。
可改主播名称、名册位置和宽度、字号、最多显示人数、滚动间隔、星光颜色、祝福位置与尺寸及显示时长。
可选择跟随系统、开启或关闭动画。关闭动画仍会显示祝福文字；明确开启时覆盖系统减少动画偏好。
画面空间不足时，会自动减少同时显示的人数，保留字号并继续滚动；名字过长时用省略号显示，可在「名册备份」中查看完整昵称。
画面宽度不超过 800 像素时，祝福/升级特效出现期间暂时隐藏名册，结束后恢复，避免文字重叠。
默认没有声音，画面不含常驻操作按钮或不透明底板。首次使用的操作提示约 5.5 秒后消失。
透明效果需要菘蓝的透明插件层，或支持透明背景的浏览器源。普通浏览器可能把透明区域显示为白色/黑色；普通窗口采集不会自动抠掉浏览器底色。

五、保存、导出和导入
名册、积分、个人冷却和设置保存在当前浏览器，本地刷新会恢复。支持最多 10000 位访客。
「名册备份」可导出完整 JSON 备份，包含真实名册和设置，演示人物不包含在内。备份含昵称及身份标识，按自己的需求保存和分享。
导入只接受此插件的 V1 JSON 备份，文件不超过 256 MB、访客不超过 10000 位。文件上限为含完整身份键的大名册留出空间；浏览器本地存储限额仍可能小于备份大小，保存不成功时不会替换。读取后显示人数预览；确认替换后才应用。预览期间收到新的真实互动，会要求重新核对。
取消、文件无效、读取过期、记录异常或保存失败均不替换当前名册。浏览器拒绝存储或空间不足时，允许本页临时使用并明确提示；关闭之前请导出备份。
存档无法读取时保留旧记录，不自动覆盖。可核对后导入有效备份恢复。
清空名册需要再次确认，建议先导出备份；清空保留外观和互动规则。
当前展示中的祝福和动画队列不在刷新后重播，避免恢复页面时重复庆祝。真实名册和积分仍会保存。

六、接入状态与排查
菘蓝插件页面内优先使用 SonglanPlugin.onChat / onGift。离开菘蓝独立打开 HTML 时，默认回退连接本机 ws://localhost:9910，可在控制台修改本机端口。
连接后会发送菘蓝的 identify 握手。SDK 延迟加载时自动切换，并停止旧 WebSocket，避免两条通道同时记分。
看到「SDK 已接入」仅说明回调接口已绑定；请以「最近收到弹幕/礼物」与实际人数变化确认直播事件是否送达。
本机菘蓝未开启时显示等待连接，会自动重试；这不影响独立预演。
模板中旧的 10030 端口不是本机菘蓝 4.0.5 的当前自定义插件默认端口。
宿主当前的真实事件未提供事件 ID，因此无法判断宿主自身是否重复广播了一份礼物。本版不会伪造事件 ID；未来上游提供 eventId/msgId 时会按事件类型与事件 ID 去重。

七、版本记录与验收范围
V2（2026-09-22）
新增：三种角色的独立卡面，同时用于名册与中央祝福/晋级；主播修改已登记观众名字。
改名路径：双击画面 → 名册备份 → 查找原昵称 → 修改名字 → 填写实际的新平台昵称 → 保存名字。头像未变时，新昵称的弹幕与礼物会继续累计原有积分，原等级、登记时间和个人冷却均保留。旧昵称不再绑定这份档案。
若新昵称已用同一头像再次登记，界面会展示两份积分之和。必须确认属于同一观众并勾选合并后保存；保留最早登记时间和较晚冷却，积分相加，只留下一个档案。合并前建议导出备份，不能拿同名但不同头像的观众自动合并。
如果确认期间积分发生变化，界面会要求重新核对合并。取消、无效名字、超额积分、存储失败或其他页面更新均不会替换旧档案。改名按确认时最新积分处理，不丢弃编辑期间正常收到的互动。
升级注意：继续使用「异世界访客登记系统-1.html」这一固定入口；内部保存键和备份结构保持兼容 V1。升级前建议在旧版先导出备份；若菘蓝重新导入分配了新的插件入口，请在新版导入旧备份。保留归档中的 V1，避免同时打开两个版本接收事件。
验收：改名继续计分、刷新恢复、编辑期间实时互动、重复档案合并、取消/存储失败保护、三档大小卡预览与透明像素均纳入测试；真实直播联调范围仍以实际完成情况为准。
