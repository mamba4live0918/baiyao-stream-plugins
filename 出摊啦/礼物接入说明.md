# 出摊啦 V1.2 · 礼物接入

1. 在菘蓝或白曜中重新导入本目录最新版 `出摊啦.html`，启用模块，把宿主新给的网址填入 OBS 浏览器来源。宿主保存的是导入时的文件快照，旧网址不会自动变成修复版。
2. 在页面里按 S，查看第①栏的实时接入状态，并打开“接收直播间互动”。“SDK已绑定”表示订阅成功；“已收礼物”表示实际收到且解析成功的消息条数，礼物份数另显示在最近礼物里。
3. 送礼物就点单（V1.2）：设置②「送礼物点单」默认“小心心 → 来1位顾客”，可加礼物、改成来 N～M 位；送几个按几份算，不受「每人同时几单」限制（那一项只管弹幕点单）；白曜规则里用礼物触发的「点单」动作也一样不受限。白曜规则里已经把某个礼物连到「点单」动作的，②里别再填同一个礼物，否则一份礼物来两位顾客。捣乱/帮忙表为空时，点“一键填入示例礼物”：人气票捣乱1次、玫瑰派1名帮手；只填空着的表，名字已用过就换一个。一个礼物名只能在点单、捣乱、帮忙其中一张表里，表外礼物仍不触发。
4. 测试一条新礼物消息：第①栏会显示最近礼物、份数和是否触发。收到但未触发时，检查②点单礼物、⑤⑥捣乱/帮忙礼物表和④捣乱池；已收数量始终不变时，检查宿主是否已启用模块、OBS是否用了新网址，以及接收开关。

设置①新增“测试礼物消息（菘蓝 / 白曜）”：展开后选择来源，点“填入示例”，或粘贴实际收到的JSON。“只解析”显示观众、uid、事件id、礼物名/份数和规则结果，不改游戏或真实收件计数；“解析并试玩”才按当前礼物表触发本地效果。坏JSON、零数量、连击结束包、表外和空礼物表会显示具体原因。菜单与实际端口共用解析流程，但不会连接真实端口，因此模拟成功不代表真实端口已连通。

菘蓝与白曜共用部分SDK接口，所以“通用接口”不等于只连接菘蓝。本版兼容 `onChat` 和 `onComment`，也支持仅存在白曜SDK的页面。

白曜的两条接法和抓萌宠一致：导入后使用独立来源网址，由宿主自动提供SDK，不需要开启“菘蓝插件端口”；直接在OBS选本地HTML时，才需要白曜开启该兼容端口。白曜弹出的插件设置窗口只改共享设置，故意不接实时礼物流；查“已收礼物”请在OBS对应来源右键“交互”，再按S查看①。

普通本地页面在没有礼物/弹幕SDK时，会尝试默认本机兼容消息端口9910、10030；宿主改过这两个端口时，优先使用宿主提供的网址。接入SDK后按消息类型接管，避免同一消息重复执行。试玩页不会主动连接本机礼物端口。

加班：V1.6 起按设置③「加班记到」，默认「自动」——在白曜里、或填了白曜给的连接码（设置③填好再点「连接」），交租差额和 overtime 动作送去白曜加班机（白曜重工 0.27.0 以上）；都不是就记到插件自带的加班机（交租牌下面的「距离下播」，礼物加减时间在设置③配）。咩播联调版已经去掉。
