# 本场直播专属宠物与单只大小设计

日期：2026-10-08（Australia/Sydney）

状态：用户已确认本设计及命名后显示名牌。最终方案为外部人工计数、插件内手动授权；实施计划待审阅与选择执行方式，尚未实施产品代码。

## 1. 最终玩法

- 主播在插件外自行记录召唤数量并判断达标，达标后在插件里手动授予取名资格。
- 先前讨论的自动累计、指定礼物门槛、插件内加减计数和菘蓝转发补丁全部取消。250 只仅是主播人工计数的参考，不是插件自动校验条件，也不新增软件门槛设置。
- 每位观众在本场直播最多拥有一只取名后的专属宠物。
- 名字、放大和保护只作用于选中的某一只宠物，同品种其他宠物不变。
- 用户追加确认：命名成功后必须显示名牌，不能只保存名字或只修改无障碍标签。
- 首次取名默认放大到这只宠物命名前目标体型的 1.5 倍，之后仍可手动调大小，改名不反复放大。
- 专属宠物持续留在场内，不被召回、龙卷风、拖回窝、普通清场或场内最高数量送走。
- 用户手动加入或上传素材的宠物同样支持单只调大小；仅调大不获得常驻保护。
- 专属宠物、观众名单和取名资格只属于本场直播。刷新继续本场，不视为直播结束。
- “结束本场并清空”经二次确认后清除全部宠物、观众名单、取名关系和待开盲盒，保留主题、素材、音量、运动范围和礼物档位等设置。
- 白曜重工和菘蓝整蛊机使用同一手动流程，沿用已有礼物接入，不修改任何宿主。

## 2. 主播操作

### 2.1 授予资格

设置中增加“本场专属宠物”区域。主播输入观众备注，点击授予资格，建立一个本场观众名额；不读取礼物 UID、昵称历史、头像身份、白曜数据库或历史贡献。

每个观众条目拥有独立持久 ownerId，不以备注文本作为长期身份。相同备注不能重复创建，界面引导选择已有条目；改备注仍使用原 ownerId。同名观众需由主播使用不同备注区分。软件保证每个名单条目最多一只，真实观众是否被重复录入由主播人工核对，不能宣称已经核验平台身份。

观众备注最多 40 个用户感知字符，去首尾空格，拒绝空值、控制字符和过长文本。用于查重的比较键采用 NFKC 规范化、首尾去空格与英文大小写折叠；展示保留主播输入的文字。修改备注不能覆盖其他条目。

名单展示“待取名”或“已取名”，以及对应宠物名字。未使用名额可以撤销，经确认后删除该条目；已有专属的条目不提供单独解除保护或换主人，直到结束本场。已授予和已使用名额随刷新保留。

### 2.2 单只操作

右键场上宠物打开网页内部的局部面板，不使用 OBS 原生弹出菜单。左键仍拖动宠物，宠物焦点下的菜单键可打开面板。面板内中文输入不触发回窝或测试快捷键，Esc 关闭面板。

普通宠物面板包含单只大小、选择已授权且未使用的观众名额、宠物名字和确认/取消。未选择有效名额时仍可调大小，但不能取名。确定取名后把原有这只宠物晋升为专属，不额外生成第二只。

专属宠物面板显示所属观众，允许改名和调大小，不更换主人、不再领取第二只。取消、所选宠物已回窝、名额已占用、素材已删除或面板属于旧本场时，不提交晋升、不改变计数。

宠物名字最多 30 个用户感知字符，去首尾空格，拒绝空名、控制字符和过长文本；支持中文、英文与表情，通过 textContent 显示，不解析 HTML。命名成功立即显示独立名牌，位于宠物上方并随位置移动；文字始终正向，不随角色翻面、倾斜或身体挤压。刷新恢复后同样显示，改名保存成功后立即更新，普通未命名宠物不显示名牌。

名牌使用原生动态文字，不写进角色素材。只公开宠物名字，不额外公开用于人工辨认的观众备注。完整名字不省略，长名字可换行，名牌在活动边缘和窄窗内保持可见，深浅直播底图均须可读。名牌不拦截鼠标，不妨碍捡起其他宠物或操作小窝；字体和局部衬底不改变透明场景。空名不能用来绕过专属保护。

名字、观众名额、晋升和大小在同一次提交中校验。选择未使用名额后，面板预填并展示首次取名的 1.5 倍比例；主播随后显式修改的比例优先，确认时直接采用该输入值，不能再乘 1.5。单只调大小不改变图鉴中的品种倍率、不改变同种其他个体。面板可分开保存大小与确认取名，避免只是调大就消耗观众名额。

### 2.3 两种清空

普通清场明确使用“清空普通宠物”语义，清场礼物也只收走普通宠物，保留专属和授权名单。

“结束本场并清空”是独立危险操作：第一次点击显示将清除全部本场宠物、名单、取名关系和盒子队列；第二次明确确认后执行。取消不改变数据，成功后开始新的空本场，不自动开盒。

## 3. 架构选择

现有普通人口系统按种类和数量保存，回窝后会合并同种个体。选择如下：

| 方案 | 影响 | 结论 |
| --- | --- | --- |
| 在普通队列内加保护标记 | 候场召回、回窝历史、翻倍、挑战和停车均需识别专属实体 | 不采用，容易混淆普通与不可收走数量 |
| 独立专属记录与场景集合 | 复用已有渲染/运动，普通队列继续按现有数量处理 | 采用；晋升时只转移原有个体 |
| 所有普通宠物都改成完整持久实体 | 能保留跨回窝的个体信息，但须重写人口和历史接口 | 本次不扩大到该范围 |

模块划分：本场命名模型负责名单、唯一拥有关系、专属记录、本场代号和恢复；局部面板负责编辑、确认和取消；app 集成负责渲染、运动、持久保存和两类集合的转移。没有自动资格计数器或新的礼物身份适配模块。

专属不进入普通 cows、positions、pendingKinds、outside、home、recentHomes 或候场。渲染/碰撞/运动使用普通与专属合并视图；收回、人口补入、翻倍和挑战只使用普通集合。收回入口再次检查保护状态，不仅依赖选择时过滤。

## 4. 本场与存档

在现有本场保存信封内增加独立 schema 的命名扩展，含 sessionId、名单、专属记录和分配编号。名单保存 ownerId、备注；专属记录保存 residentId、ownerId、名字、原 kind、个体大小和归一化位置。一个 ownerId 不能关联多个 residentId。

晋升在一个候选状态内完成：核对当前 sessionId、活着的普通实例、未使用名额、有效 kind/name/scale；普通 outside 减 1，home 不增加；从普通集合转移原实例到专属集合。总实际宠物数量不变，普通与专属数量分别改变。没有资格消耗在宠物晋升之前单独保存的中间状态。

创建/撤销名额、改名、晋升及结束本场都先保存完整候选快照，再提交运行状态和界面。读取当前状态、构造/校验候选、localStorage 写入和提交须在同一个同步回调中完成，其间不 await，也不使用异步缓存的旧候选；异步输入完成后重新读取当前本场并核对运行世代。写入失败不改变拥有关系、不执行清空，保留旧存档并提示；不声称已经可靠保存。存储不可用时普通玩法及临时单只调大仍可使用，但不能完成可靠的专属授权或命名。

刷新恢复相同 sessionId、名单和专属，不自动开新场。旧存档没有命名扩展时从空名单开始，保留普通人口，不从旧礼物或头像补造资格。坏扩展进行结构校验、唯一键校验与引用校验，不让重复 ownerId/residentId 创建两只；保留健康数据并提示，不静默覆盖原始坏档。遇到无法判明是否已领取的坏关联时，阻止相关名额再次使用直到结束本场，不猜测为“未领取”。隔离字段保留原始坏扩展及冻结关联，所有后续普通自动存档或编辑快照都须携带这些字段，不能刷新后重新开放名额；归属范围无法判定时暂停新授权/晋升，不暂停普通玩法，主播仍可结束本场清除隔离数据。

浏览器存档属于当前插件实例；两个工具都可独立使用，但本次不增加跨浏览器、跨宿主或多电脑的名单同步。

## 5. 结束本场

最终确认时构造一个新的空本场并生成新 sessionId。清除普通场上/候场/小窝、positions/pendingKinds/recentHomes 等回窝与恢复历史、专属宠物、名单与取名关系、隔离坏数据、当前盒/排队盒/pendingGifts、头像本场引用、龙卷风/强化抓手/挑战/点赞累计等本场效果；全部本场业务统计归零，包括 outside/home/queue，停止自动开盒和播放。不能在新场通过爆窝或自动补位重新生成旧宠物。

先保存新空本场，成功后提交状态并清理旧 DOM、飞行、盒子奖励、编辑面板及异步加载回调。可能在清空后完成的异步回调必须验证 sessionId/运行世代，不得恢复旧宠物。保留有界的最小传输去重信息防止已收事件立即重放，但不保留已清空的观众备注、授权或拥有关系。

确认期间收到的新礼物仍归旧本场；确认后一起清掉，取消则保留。旧队列和已经开始的动画不能在新场发奖励。无法从旧宿主载荷判断尚未到达的网络旧消息时，不宣称已能拦截该类消息；本次不改已有宿主协议。

清空不改配置：主题、上传图片/逐帧、音效、字体、运动范围、音量、全局/品种大小、场内最高数量及盲盒档位全部保留。专属的个体大小随专属清除，不变成品种设置。

本次没有可靠的自动直播结束检测，不因短暂断连、刷新、切主题自动归零，由主播结束直播时主动确认清空。

## 6. 保护、大小与素材

保护覆盖键盘回窝、拖回窝、强化抓手批量回收、普通召回、候场召回、龙卷风、清场礼物、普通清场、翻倍、回窝历史、爆窝与人口停车。专属可被主播单只拖动定位，落在窝图片上时仍放回活动区域，不增加 home；抓普通宠物时不额外抓起附近专属。

场内最高数量只约束普通宠物，专属数量单独显示。普通清空挑战只检查普通人口，不因专属常驻永远无法完成。切换主题保留专属归属、名字、原品种和尺寸；普通动物沿现有主题规则显示，已命名非鸭宠物不强制改成鸭吉吉。

上传品种被专属引用时拒绝删除并明确提示，不能先删 IndexedDB 素材再把专属改成其他动物；结束本场后可正常删除。专属使用头像 kind 时参与头像引用检查，防止编号被回收给其他头像；不把头像当观众身份。

每只宠物的个体比例默认 100%，以现有全局大小乘品种倍率为基准。编辑范围为 25–1000%，最多两位小数；首次命名的预填比例为当前比例乘 1.5 并保留两位小数，超过 1000% 时截断且明确提示。主播覆盖预填后直接采用输入值；提交命名及后续改名不再累乘。空值、非有限数、范围外编辑不提交，不让显示值与实际值不同。

最终可见尺寸仍经过现有视口和活动范围 fit，面板区分目标比例与空间限制后的实际大小，放大不突破运动区域。普通 positions/候场快照增存个体比例，旧记录默认 100%；普通单只大小随刷新和停车保留。

普通宠物仍沿用按种类合并的回窝历史，不增加跨回窝的永久个体身份；后续从窝生成的普通宠物使用该品种默认体型。专属不进入这条链路。

HTML/body/场景保持透明，只显示物件、名字和必要局部面板。已有动物/配饰图片和动效保持原样，不新绘角色、不改原身体素材、不添加营销式说明页面。

## 7. 验收

- 手动授权、重复备注、同名人工区分、改备注不新增名额、撤销未用名额、一名额一只、禁止换主人与改空名。
- 只改所选个体、自定义上传/手动加入宠物大小、首次放大与改名不叠加、中文/表情完整名字、HTML 字符串、失效选择与旧本场面板。
- 命名后立即显示名牌、随位置移动但不翻面/倾斜、刷新恢复显示、改名同步、不展示观众备注、不拦截捡宠物或小窝交互。
- 各回收路径、候场、普通场内上限、翻倍、清空挑战、主题切换、引用素材删除保护、头像 kind 引用和普通宠物计数。
- 同场刷新、旧存档迁移、坏扩展、重复引用、写入拒绝/满额、授权/晋升/清空保存失败不损坏旧数据。
- 结束本场二次确认、取消、期间新礼物、旧盒动画/加载回调、停止自动开盒、空本场恢复及所有设置保留。
- 透明叠层、深浅直播底图、窄窗、长名字、活动边缘、单只大小与运动限制、键盘与中文输入不串入场景快捷键。
- 白曜与菘蓝沿用原礼物功能，手动授权流程不依赖两者的 UID、来源或新协议；真实工具测试与 Node 合成测试分别记录。

实施后运行既有回归和新增测试，验证构建 HTML 的内嵌脚本及实际包内文件；保留 V1.0.20 及更早 ZIP/PDF 和原身体素材。浏览器/OBS 未实测时明确标注，不以离线模型测试替代真实宿主验收。
