## 3. 自适应尺寸

### 3.1 公式（新增一个纯函数，放在 `core.js` 或新的 `src/layout-scale.js`）

```
short = min(W, H)                      // W,H = innerWidth, innerHeight
stageScale = min(1, short / 1080)      // 舞台元素：只缩小，不放大
textScale  = max(stageScale, 0.65)     // 直播画面上带文字的部件：保证可读
orientation = W / H < 0.9 ? 'portrait' : 'landscape'
```

| 画面 | stageScale | textScale | 方向 |
|---|---|---|---|
| 3840×2160 / 2560×1080 / 2048×1536 / 1920×1080 | 1 | 1 | 横屏 |
| 1280×720 | 0.667 | 0.667 | 横屏 |
| 1080×1920 | 1 | 1 | 竖屏 |
| 720×1280 | 0.667 | 0.667 | 竖屏 |
| 390×844 | 0.361 | 0.65 | 竖屏 |
| 1080×1080 | 1 | 1 | 横屏（W/H=1） |

### 3.2 乘以 stageScale 的舞台元素

渲染和碰撞判定都要按缩放后的尺寸：

- 萌宠基础大小：`size()` 改为 `min(prefs.size*stageScale, W*.5, H*.5)`。品种比例、单只比例、`fitSize` 的逻辑不变。
- 小窝宽度：`penGeometry` 增加 scale 参数，`min(penWidth*stageScale, W*.65, H*.7/aspect)`。拖动缩放手柄时，保存的值 = 显示宽度 ÷ stageScale（`customize.js` 约第 191 行 `resizePen`）。滑杆 `penWidthRange` 仍然显示 1080 基准值。
- 盲盒宽度：`applyLayout` 中两种模式都用 `showWidth*stageScale` 参与现有的 `min(...)`。
- 精灵球：`cfg.ballSize*stageScale`。
- 龙卷风半径、抓手半径：`tornadoRadius*stageScale`、`gripRadius*stageScale`。显示圈和抓取、收取判定都用缩放后的值。
- 粒子位移（P2，可选）：spark `--dx` 和上升高度、盲盒碎片飞行距离也乘以 stageScale。

### 3.3 乘以 textScale 的直播文字部件

- 统计栏、入场提示：有效比例 = `cfg.scale/100 × textScale`，之后套用 `hudGeometry` 现有的"放不下就再缩"逻辑。`hud.js` `apply()` 里 `innerWidth<600` 的特例删掉，由 5.1 的通用避让规则代替。
- 互动面板：视觉尺寸 × textScale，并且始终在画面内。`placePanel` 要用缩放后的实际尺寸做夹取。
- 名牌：字号 14 px 和最大宽 220 px × textScale。缩放变化时要让 `measureRevision` 递增，重新测量。
- toast 提示：字号和内边距 × textScale。

### 3.4 不缩放（主播操作界面，已有响应式 CSS）

设置面板 `#settings`、单只宠物面板 `#pet-panel`、底部操作栏 `#toolbar`、齿轮 `#settings-btn`。

### 3.5 设置项的含义和文案

数值和范围都不变，含义统一为"1080 画面下的像素"。涉及的设置项：萌宠基础大小、盲盒大小、精灵球大小、抓取范围、作用半径、小窝大小滑杆、统计栏缩放。

在「萌宠基础大小」下面和「位置与蹦跳」页各加一行说明：

## 4. 横屏 / 竖屏各记各的布局

### 4.1 哪些是布局字段（按方向分别保存）

| 字段 | 旧来源 |

| 吟唱模式盒子位置 `show.{x,y}` | `pet-catch-v1-custom` 的 showX / showY |
| 统计栏 `hud.stats.{x,y,scale}`、入场提示 `hud.waiting.{x,y,scale}` | `pet-catch-hud-v1` |
| 互动面板 `panel.{x,y}` | `pet-catch-effects-v1` 的 panelX / panelY |

以下保持全局，不分方向：小窝锁定 `penLocked`、盲盒大小 `showWidth`，以及第 3.5 节列出的各种大小设置。

### 4.2 存储（遵守"格式变了就换新 key"规则）

新 key 为 `pet-catch-layout-v2`：

```json
{"version":2,"landscape":{...},"portrait":{...}}
```

- **读取**：有新 key 就只用新 key。没有时迁移，然后立即写入新 key：
  - 横屏：取旧字段的当前值。
  - 竖屏：按组判断（小窝、活动范围、盒子位置、统计栏、入场提示、互动面板各算一组）。旧值等于出厂横屏默认值（用户没动过），这一组取第 4.4 节的竖屏默认值；用户动过，这一组沿用旧值。
  - 这样原本就在竖屏下调好布局的人，升级后什么都不变；没调过的人，竖屏直接得到更合适的默认值。
- **校验**：每个值按现有范围检查（x/y 0–100，活动范围最小跨度 5%，scale 50–250，penWidth 120–800）。不合格的字段回退到该方向的默认值。
- **写入**：
  - V1.0.41 不再写 `pet-catch-hud-v1`。
  - `pet-catch-v1-custom` 和 `pet-catch-effects-v1` 里的布局字段，原样写回启动时读到的值（冻结）；其它字段照常保存。
  - 这样回滚到 V1.0.40 时，看到的是升级前的布局；再升级回 V1.0.41，用的是新 key 里最新的横竖屏布局。
- 白曜的插件存档按插件 id 保存。用白曜的"更新插件"可以保留插件身份和存档（V1.0.39/40 说明已写），新 key 会跟着同一份存档走。

### 4.3 运行规则

- 启动时和每次尺寸变化时，判断方向并套用对应布局：小窝、活动范围、统计栏、入场提示、互动面板、盒子位置。
- 拖小窝、缩放小窝、框选活动范围、拖动或缩放统计栏、放置盒子或面板，都只改当前方向的布局。
- 四个重置按钮（「恢复默认位置」×2、「恢复默认范围」、「重置统计与入场布局」）只重置当前方向，按钮文字后面带上方向，例如「恢复默认位置（当前：竖屏）」。
- 「位置与蹦跳」页顶部加一行只读状态：`当前画面 1080×1920 · 竖屏布局（横屏、竖屏的位置分别保存）`。
- 方向切换时，萌宠按在旧活动范围里的相对位置 (u,v)，映射到新活动范围的同一相对位置，而不是挤到新范围的边上。没有切换方向的普通尺寸变化，沿用现有的按比例换算。

## 5. 防重叠规则（只影响显示，不改存档）

画面变大后，能自动恢复用户原来放的位置。

1. **统计栏 / 入场提示 vs 齿轮**：外扩 8 px 后相交，就把这个部件移到齿轮正下方（y = 齿轮底部 + 8 + 半高），x 不变。
2. **盲盒 vs 小窝**（盒子显示时）：外扩 12 px 后相交，按以下顺序处理：
   1. 把盒子水平移到小窝左右两侧中较宽一侧的空白中央；
   2. 放不下就移到小窝上方；
   3. 仍然放不下，就把盒子缩到不小于 70%。
   4. 盒子永远不隐藏；实在无法避开时，盒子画在小窝之上。
3. **统计栏 vs 小窝**：重叠时移动统计栏，小窝不动。
4. 所有直播部件保持在画面内，留 8 px 边距（沿用现有夹取）。

- 不新增常驻重绘。
- 性能验收：1500 只（1920×1080 和 1080×1920，WebGL2）帧率不低于 V1.0.40（在测量波动范围内）。每个点测两轮。

## 10. 注意事项

- 多个测试会把 `app.js` 按函数标记切片，单独在 vm 里执行，例如：
  - `function sequenceFrame(` … `function penRect(`
  - `function tick(` … `function openSettings(`
  - `function size()` … `function ballBurst(`
  - 用 `line('allActors')` 取单行函数。

  新函数如果在这些切片里被调用，要放在同一切片内，或用 `typeof` 保护。每次改动后都跑全量测试。
- 素材清单里的内置动物没有 `kind` 字段，kind 就是数组下标。用测试数据播种时，不要读 `c.kind`。
- 插件有两种运行方式，都要验证：
  1. OBS 浏览器源 → 菘蓝 `plugin-viewer`（iframe srcdoc），画面 = 浏览器源尺寸；
  2. 白曜画布，画面 = 设计尺寸 2048×1536。
- 直播时段停止重负载测试：北京时间 07:01–09:01、18:01–20:01（悉尼时间 10:01–12:01、21:01–23:01）。
- 以前遇到的坑：
  - Playwright 的时钟驱动不了 rAF；
  - Worker 里 OffscreenCanvas 生成的 GPU ImageBitmap，在 Worker 结束后会画成空白；
  - 跨域头像不能上传成 WebGL 纹理。

  做像素对比时注意这些。
