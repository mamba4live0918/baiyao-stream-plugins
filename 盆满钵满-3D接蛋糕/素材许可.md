## 内嵌方式说明

每个模型由 `<name>.gltf`（JSON）、`<name>.bin`（buffer）与同目录共享贴图 `tiny_treats_texture_1.png`
（1024×1024 PNG 渐变图集，13 个模型共用）组成。构建脚本将其合并为 **GLB 2.0 单文件**：

1. **header**：12 字节 —— `magic = "glTF"`、`version = 2`、`totalLength`（整个文件字节数）。
2. **JSON chunk**：glTF JSON，按 4 字节对齐，不足处用空格（`0x20`）padding；长度字段含 padding。
3. **BIN chunk**：二进制数据，按 4 字节对齐，不足处用 `0x00` padding；长度字段含 padding。
   - 原始 `.bin` 的字节与所有 `bufferViews` 的偏移**保持不变**，只把 `buffers[].uri` 移除并合并为一个内嵌 buffer；
   - 贴图 PNG 二进制追加到 BIN 末尾（4 字节对齐），新增 `bufferView`，`images[].uri` 改为
     `{ bufferView, mimeType: "image/png" }`，因此 GLB 内**不存在任何外部资源引用**。
4. 13 个 GLB 再以 **base64**（无换行）内嵌到 `src/cc0-data.js` 的 `CC.CC0_DATA.models[kindId].glb`，
   同时记录 `bytes`（GLB 字节数）与 `triangles`（三角面数）。该文件是 IIFE，浏览器挂到 `window.CC.CC0_DATA`，
   Node 端 `require()` 直接返回数据对象（`module.exports`），不依赖 ES Module。

同时保留可追溯的中间产物：

- `assets/cc0/source/<name>/`：原始 `.gltf`、`.bin`、贴图备份（逐字节保留下载内容）；
- `assets/cc0/glb/<kindId>.glb`：合并后的单文件 GLB（与 `src/cc0-data.js` 内嵌内容一致）；
- `assets/cc0/TinyTreats-LICENSE.txt`：原始许可文件全文；
- `docs/cc0-assets-report.json`：逐模型字节数 / 三角面 / 材质 / 贴图与总计报告。

### 使用示例

```js
// 浏览器：index.html 按序加载 src/cc0-data.js 之后
const meta = CC.CC0_DATA.models.cc0_birthday;
const bin = atob(meta.glb);
const bytes = new Uint8Array(bin.length);
for (let i = 0; i < bin.length; i++) bytes[i] = bin.charCodeAt(i);
new THREE.GLTFLoader().parse(bytes.buffer, '', (gltf) => { scene.add(gltf.scene); });

// Node：读取全部数据（无需网络）
const CC0 = require('./src/cc0-data.js');
const buf = Buffer.from(CC0.models.cc0_birthday.glb, 'base64');
```
